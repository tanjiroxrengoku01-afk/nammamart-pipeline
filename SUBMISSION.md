## Part A: ETL pipeline

*Five parallel extract tasks; Python rules in `include/nammamart_helpers/quality_rules.py`; Critical rows go to `include/quarantine/slick/` with a `failure_reason`; email and phone are masked; star schema `etl_fact_orders` + three dimensions; idempotent load (delete the keys, then insert); reconciliation table.

**Design decision to explain:** a dimension row that fails a Critical rule is quarantined, but if a clean order still points at it, the row is loaded as `REPAIRED` (failed field blanked or `Unknown`). Example: store S07 has a blank zone, so it is quarantined and also loaded with zone `Unknown`, and its 171 orders keep their revenue.

## Part C: Scheduling

- **Cron expression:** `0 9 * * 1-6` (9:00 AM, Monday to Saturday).
- **Timezone:** `start_date=pendulum.datetime(2026, 10, 1, tz="Asia/Kolkata")`.
- **default_args:** `retries=2`, `retry_delay=1 minute`, `execution_timeout=10 minutes`. **TODO:** one line on why each value (for example, retries cover short file or lock problems; the timeout stops a stuck task).
- **catchup=False. Justification, :** the pipelines load the current state of the files, so running every past date would repeat the same work and add nothing; the files carry no date partition.
